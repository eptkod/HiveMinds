# HiveMinds guide

The details behind the [README](../README.md): where HiveMinds keeps things, how each feature works under the hood, and how to test it.

## Where things live

- Settings: Cmd+comma. Saved in UserDefaults (`com.ethan.hiveminds`), so they survive restarts.
- App data: `~/Library/Application Support/HiveMinds/` holds `state.json` (projects, agents, browser and shell tabs), the Claude settings files agents start with (`claude-hooks.json`, plus `claude-hooks-api-key.json` and `claude-api-key.json` for API-key sign-in), `statusline.sh` and `usage.json` for the plan usage meter, and per-agent event logs.
- Project workspace: pick a project's "Canvas" row to see every agent's terminal and every browser tab at once, each usable in place (drag a tile by its title bar to move it, or by any edge or corner to size it; double-click an edge to fit it automatically again). Tabs along the top switch between agents, browser tabs, shells and meetings (Cmd+T for a new browser tab, Shift+Cmd+T for a new shell in the project's folder, Cmd+G for the Canvas). Each of the project's meetings shows on the Canvas as a chat of what its seats say and write, then its outcome once it's finished; its X only takes it off the Canvas.
- Voice dictation (optional, off by default): Settings > Voice. Hold Right Option, talk, let go, and the words are typed into the terminal or text field you're in. For longer dictation, press Space while holding the key: it keeps listening after you let go (hands-free), and a tap of the key finishes. Esc cancels. If the text doesn't land (no field focused, or a new agent still starting), Edit > Type Last Dictation Again (⌥⌘V) types it again; Edit > Copy Last Dictation and the ⌘P palette copy it. The last 5 are kept in memory only, and nothing goes on the clipboard unless you pick it. Apple's on-device engine works with no setup; Whisper models download to `~/Library/Application Support/HiveMinds/Voice` and can be removed from the same tab. The Whisper helper is built by `scripts/build-whisper-helper.sh` (called by `build-app.sh`; `HIVEMINDS_NO_WHISPER=1` skips it). Debug test: `HIVEMINDS_TEST_DICTATION=<16 kHz mono wav> build/HiveMinds.app/Contents/MacOS/HiveMinds`.
- API keys: Settings > Accounts lets Claude Code and Codex each sign in with an API key instead of your plan. Keys are kept in the macOS Keychain ("HiveMinds API key"), never in a file.
- Projects cloned from GitHub: `<projects folder>/<repo>`. HiveMinds asks for the folder the first time and remembers it; change it in Settings > Projects. An existing checkout (including Agent Office's) is reused.
- Code layout: the agent logic that HiveMinds Host will share (agent model, the `claude`/`codex` command line, what hook events mean, the keys that answer prompts, git worktrees and changes, terminal snapshots) is in `Sources/HiveMindsCore`, with tests in `Tests/HiveMindsCoreTests` (`scripts/test-core.sh`). The app (`Sources/HiveMinds`) keeps the screens, the store and the terminals on This Mac. SwiftTerm is vendored in `Vendor/` (`Vendor/README.md` lists the patch).
- Testing answers from a tile with real agents (debug build, each in its own scratch git repo and `HIVEMINDS_SUPPORT_DIR`): `HIVEMINDS_TEST_ASK=<repo>` (a permission, then two questions), `HIVEMINDS_TEST_PLAN=<repo>` (plan mode, approved as a tile does; add `HIVEMINDS_TEST_PLAN_ACCESS=manual` for Manual review, `HIVEMINDS_TEST_PLAN_FEEDBACK=1` to send the plan back once first, `HIVEMINDS_TEST_PLAN_SCREEN=1` to print the terminal). `HIVEMINDS_TEST_STARTUP=<folder>` prints Claude Code's first screen from an agent that was never shown or resized.
- Branding (logo, app icon, colours): `branding/`. Change `branding/scripts/render.swift`, run `branding/scripts/render.sh`, then rebuild the app.
- Agents on their own branch: `<project>/.hiveminds/worktrees/<title-slug>-<id>`.
- Pull requests: an agent on its own branch has a pull-request button in its header. It drafts a title and description, then pushes the branch and opens the PR with `gh` only when you confirm. PRs an agent opens itself are picked up after its turn ends.
- Meetings (the Meetings switch in the toolbar, or Shift+Cmd+N): each runs in its own worktree, `<project>/.hiveminds/worktrees/meeting-<topic>-<id>` on branch `hive/meeting-…`. Turn notes go in `.hiveminds/meetings/<date>-<topic>/` inside it, and the outcome in `meetings/<date>-<topic>.md`, committed on the meeting's branch. When a meeting finishes, its outcome (a review panel's combined review too) is also saved in the project's own folder at `<project>/meetings/<date>-<topic>.md`; the folder is set in Settings > Meetings. Meeting defaults are in Settings > Meetings.
- Hidden projects: a project's … menu in the sidebar has Hide Project. It leaves the sidebar, its agents are stopped (they keep their chats), and it's listed in Settings > Projects > Hidden projects with a Show button.
- Delete many agents at once: press the trash button in the Canvas tab row or above the Overview's agents (or ⌘-click an agent) to enter select mode, tick agents, then Delete N… in the bar at the bottom. Select Finished ticks every agent that isn't working or waiting on you. A project's … menu also has Delete Finished Agents….
- Agent history (sidebar > History, ⌘Y): every agent, including deleted ones. Deleted agents are kept in `~/Library/Application Support/HiveMinds/agent-history.json`, up to a count and number of days set in Settings > Agents > History (default 100 agents, 7 days).
- Region check (optional, off by default): Settings > Location. On Wi-Fi, at launch and again whenever the network changes or the Mac wakes (`NWPathMonitor` and the wake notification, no polling), HiveMinds asks Cloudflare (`cdn-cgi/trace`) for the country of this Mac's internet address and checks it against the supported-country lists for the default provider and any provider an agent is running on (`LocationCheck.swift`). If one isn't offered there, every agent and meeting stops, the window's content is hidden, and an error offers Quit HiveMinds or Turn Off Region Check (so a wrong answer can't lock you out). Off Wi-Fi it doesn't check; if the country can't be found, the app carries on (with a warning at launch). It never uses Location Services, only the country code is read, and nothing is saved. A VPN changes the result. Debug tests: `HIVEMINDS_TEST_LOCATION=<country code>`, `nowifi`, `unknown` or `live` (add `HIVEMINDS_TEST_LOCATION_URL=<url>` to test a bad reply); `HIVEMINDS_TEST_LOCATION_CHANGE=<code>` fakes a network change 3 s after launch (`HIVEMINDS_TEST_LOCATION_CHANGE_AFTER=<s>` to change the wait); `HIVEMINDS_TEST_LOCATION_PRESS=<png>` with `HIVEMINDS_TEST_LOCATION_BUTTON=1|2` presses Quit or Turn Off.
- Keep awake (optional, off by default): Settings > Agents > Sleep. While any agent is working, the display won't turn off and the Mac won't sleep. Check it with `pmset -g assertions | grep HiveMinds`.
- Usage history of deleted agents, kept for the Overview charts: `~/Library/Application Support/HiveMinds/history.json`.
- Per-agent status line snapshots (cost and tokens, used for meeting totals): `~/Library/Application Support/HiveMinds/status/<agent id>.json`.
- Token badges (tokens used and the API-price estimate, top right of every agent, meeting and Canvas header): code in `Sources/HiveMinds/TokenUsage.swift`. Each agent's cost and transcript paths are saved in `~/Library/Application Support/HiveMinds/spend.json`; tokens are counted from Claude Code's transcripts.
- Split up (New Agent > Split up): `SplitUp.swift`. One `claude -p` call (Sonnet, low effort, read-only `Read`/`Glob`/`Grep` tools, `--json-schema`) returns the tasks; each becomes an agent via `createAgent(..., title:, open: false)`. The most agents per request is Settings > Agents > Split up. Debug test: `HIVEMINDS_SUPPORT_DIR=/tmp/x HIVEMINDS_TEST_SPLIT=/path/to/git/repo build/HiveMinds.app/Contents/MacOS/HiveMinds` splits a three-bug request and prints the agents it made (add `HIVEMINDS_SPLIT_MODEL=nope` to check the one-agent fallback).
- Testing a meeting without touching your real state (debug build): `HIVEMINDS_SUPPORT_DIR=/tmp/x HIVEMINDS_TEST_MEETING=/path/to/git/repo build/HiveMinds.app/Contents/MacOS/HiveMinds` runs a short Haiku debate and prints its progress. The repo must be in a folder Claude Code already trusts.
- README screenshots (debug build): `HIVEMINDS_SUPPORT_DIR=<copy of your app data> HIVEMINDS_SNAPSHOT=<path prefix> HIVEMINDS_DEMO=<scratch git repo> build/HiveMinds.app/Contents/MacOS/HiveMinds` starts four Haiku agents and a short meeting in that repo (unrestricted, so use a throwaway one), then saves `<prefix>-canvas.png`, `-agent-working.png`, `-meeting-outcome.png`, `-overview.png`, `-history.png` and a few more. The window captures itself, so no screen-recording permission is needed, and it's drawn on solid black. Shrink them with `sips -Z 1800` into `docs/screenshots/`.

## HiveMinds Host (in progress)

`hiveminds-host` (`Sources/hiveminds-host`) runs agents on a machine with no window, for paired devices on the local network. The spec is `docs/LINUX-HOST-SPEC.md`; the protocol is `docs/HOST-PROTOCOL.md` (version 1). The host, the app's side and the packaging are done; the packages aren't published yet.

- Commands: `serve [--name NAME] [--port 7420] [--listen ADDRESS]`, `projects add FOLDER [--name NAME]`, `projects list`, `projects remove FOLDER|NAME`, `pair`, `devices list`, `devices revoke NAME`, `status`, `log [--follow]`, `--version`. Only registered project folders are offered.
- Pairing: `serve` shows a 6-digit code (60 s, single use, 3 tries; `p` for a new one). The device proves it has the code with SPAKE2 over its TLS connection, then the host asks `Allow "<device>" (fingerprint …) to use this host? [y/N]`. A host started without a terminal (systemd) shows codes and asks in `hiveminds-host pair`, run from any terminal on that machine. Tokens are kept as hashes only, tied to the device's certificate, and expire after 90 days unused.
- Network: TLS 1.3 both ways (self-signed P-256 certificates, pinned by fingerprint), WebSocket at `/hiveminds/v1` with `Host: hiveminds`; requests with `Origin` or `Cookie` are refused. It listens only on this machine's private addresses (not VPN tunnels or AirDrop's peer-to-peer links) and follows address changes; peers from non-private addresses are refused even with `--listen`. Discovery: `_hiveminds._tcp`, named `hiveminds-<id>`, TXT `v=1 id=<host id>` only (Bonjour on macOS, Avahi's `libdns_sd` on Linux, loaded at run time).
- Team use: any number of devices can watch an agent; one types at a time (the first to type, or whoever presses Take Over); control lets go after 30 s without typing or when that device leaves. The agent's terminal takes the typing device's size; watchers get a fresh snapshot when it changes. The first answer to a prompt wins and everyone sees who answered.
- Files (XDG, also on a Mac): settings `~/.config/hiveminds-host/config.json` (name, projects); data `~/.local/share/hiveminds-host/`: `agents.json`, `started-by.json`, `history.json` (deleted agents), `devices.json` (paired devices, token hashes), `host-id`, `identity/` (the host's key and certificate), the Claude Code hook settings, per-agent event and status files; state `~/.local/state/hiveminds-host/`: `serve.lock`, `audit.log` (one JSON object per line: who connected, paired, was refused, created, took control, answered, deleted or was revoked; never what was typed). Folders are 0700 and files 0600.
- `status`, `devices`, `pair` and the debug commands talk to `serve` over a Unix socket: `$XDG_RUNTIME_DIR/hiveminds-host.sock`, else `~/.local/state/hiveminds-host/hiveminds-host.sock`, else (a long home path) `/tmp/hiveminds-host-<uid>/<hash>.sock`. The socket is 0600 and a connection from another user is closed. `hiveminds-host debug paths` prints the paths in use.
- Agents use this machine's Claude Code login and its git, `gh` and SSH keys. Each runs in its own pseudo-terminal and process group (`PTYProcess`, with its start-up in C in `Sources/CHiveMindsSystem`), with a headless terminal keeping its screen (`AgentSession`). The command line, hook handling and prompt answers are the same `HiveMindsCore` code the app uses. The network code is `Sources/HiveMindsNet` (server, client, pairing, gate, discovery) and the messages `Sources/HiveMindsProtocol`.
- Stopping: Ctrl+C with agents running asks first (Ctrl+C again forces); SIGTERM (`systemctl stop`) and a closed terminal stop without asking. Connected devices are told first (`hostStopping`). Each agent gets SIGTERM, then SIGKILL after 3 s. Nothing is left running.
- In the app (`Sources/HiveMinds/Hosts.swift`, `RemoteHost.swift`, `RemoteTerminal.swift`, `StoreRemote.swift`, `HostViews.swift`, `HostKeychain.swift`):
  - Settings > Hosts: look for hosts on the network (`hosts.discover`), connect at launch (`hosts.autoConnect`), the name hosts and teammates see (`hosts.displayName`, default the Mac's name), the paired hosts with Pair Again and Forget, and Pair by Address…. Hosts nearby show in the sidebar under "On this network" with Pair….
  - This Mac's identity (one key and certificate for every host) and each paired host (id, name, pinned fingerprint, token, last address) are in the Keychain, service "HiveMinds host pairing". Nothing about hosts is saved in `state.json`.
  - The sidebar shows This Mac's projects, then each host with its status and projects. A host's projects and agents are merged into the app's lists with a host tag (`remoteProjectHost`, `remoteAgentHost`) and actions go to the host as requests, so tiles, cards, tabs, prompts, Changes and History work as for local agents. Its terminal is a plain SwiftTerm view fed from the host (`RemoteTerminalView`), drawn at the agent's size and scaled to fit; the terminal's own answers to the program are dropped, since the host's terminal answers.
  - Not for hosts in v1: meetings, Split up, shell and browser tabs, attachments, pull requests, Restart With, Show in Finder. The app reconnects with backoff (1 s up to 60 s; 60 s after "was stopped"), and discovery seeing the host again retries at once. A connection that's up costs nothing while idle.
  - Debug test: `scripts/test-app-remote.sh` runs a local host with a stand-in CLI, the debug app (scratch `HIVEMINDS_SUPPORT_DIR` and `HIVEMINDS_HOSTS_FILE`, which keeps the pairing in files instead of the Keychain) and the test client as a second device, through `HIVEMINDS_TEST_REMOTE` (`DebugRemoteTest.swift`): pairing, an agent, its screen, Take Over, a refused answer, Allow, Changes, quitting, coming back, delete, History, the host stopping. `KEEP=1` keeps its logs; `SNAP=<prefix>` saves window captures.
- Installing: the AUR package `hiveminds-host-bin` (`packaging/aur/`; a prebuilt x86_64 binary with Swift built in) or `hiveminds-host` (from source, needs `swift-bin`). As a service: `systemctl --user enable --now hiveminds-host` (`packaging/hiveminds-host.service`), `sudo loginctl enable-linger $USER` to run while logged out, `journalctl --user -u hiveminds-host` for its output, and `hiveminds-host pair` for codes and the yes/no, since a service has no terminal. Discovery needs `avahi-daemon` running. With a firewall, allow 7420/tcp and 5353/udp (`sudo ufw allow …`).
- Making the tarball: `scripts/build-host-linux.sh` on Linux; `scripts/build-host-x86_64.sh [tag]` from the Mac (an Ubuntu 24.04 x86_64 chroot in the Lima VM, running under Rosetta, so the binary runs on glibc 2.39 and newer distributions (it asks for 2.38 or newer)). It also updates the version, tag and checksum in `packaging/aur/` and regenerates `.SRCINFO` (`scripts/aur-srcinfo.sh`).
- Hidden debug commands, for testing a host without the app:
  - on the host: `hiveminds-host debug start PROJECT --task "..." [--model haiku] [--access auto|manual|unrestricted] [--plan] [--own-branch] [--trust] [--follow] [--timeout S]`, then `debug follow|screen|type|keys|respond|stop|restart|delete ID` (an id prefix is enough); `debug pair-code`, `debug pair-allow`, `debug pair-deny`. `--trust` answers Claude Code's "trust this folder?" by reading the screen. `HIVEMINDS_HOST_CLAUDE=<path>` swaps in a stand-in CLI.
  - a test client, standing in for the app over the network: `hiveminds-host debug remote ADDRESS[:PORT] pair CODE|hello|projects|agents|create PROJECT --task …|attach ID [--seconds N]|take ID [--type TEXT] [--seconds N]|type ID TEXT|keys ID KEYS|answer ID ACTION|changes ID|delete ID|history`, with `--name`, `--fresh` (a new identity), `--origin`, `--host-header`, `--path` and `--protocol` to test the defences. It keeps its identity and tokens in `~/.local/state/hiveminds-host/test-client/`.
- Testing on CachyOS (or any Linux machine), and from the Mac across the network: `docs/HOST-TESTING.md`; `scripts/copy-to-linux.sh user@address` copies the source there over SSH.
- Tests: `scripts/test-app-remote.sh` (the app against a local host, above), `scripts/test-host.sh` (agents and stopping, with a stand-in CLI that writes hook events like Claude Code; `--real` for the real Claude Code with Haiku) and `scripts/test-host-network.sh` (pairing, the defences, the audit log, the mDNS record, two devices sharing an agent; on Linux, `--non-private 203.0.113.5` after `sudo ip addr add 203.0.113.5/32 dev lo` also checks a non-private peer is refused).
